# Source traceability
Capture only durable facts supported by current changed code, the ticket, plan, review and real evidence. Treat chat memory as pointers, not proof. Cross-check every reported changed file with Git status/diff or committed changes; if a path is unrelated, remove it or mark the scope unresolved. Separate **observed behavior**, **design rationale**, **test evidence**, and **remaining assumptions**. Never imply CI passed, QA accepted or deployment happened unless verified separately. Cite repository-relative source paths and acceptance IDs in narrative when useful; the manifest contains a concise summary, not raw transcripts.
